# 用原生库加速命令规则匹配

当命令规则较多时，可以让 AgentMoss 先用原生库排除不可能命中的规则，再由 Python 检查剩余规则。该功能默认关闭。常规部署可直接使用[项目快速开始](../../README.md#快速开始)。

## 准备动态库

在运行 AgentMoss 的 Linux 主机或容器内准备与 CPU 兼容的动态库。AgentMoss 安装包不包含这些库。

| 平台 | 后端 | 动态库来源 |
| --- | --- | --- |
| 鲲鹏 aarch64 | `ultrascan` | [BoostKit Ultrascan 5.8.0 安装指南](https://gitcode.com/boostkit/Ultrascan/blob/Ultrascan-v5.8.0/docs/zh/installation_guide.md) |
| x86_64 | `hyperscan` | [Intel Hyperscan 构建指南](https://intel.github.io/hyperscan/dev-reference/getting_started.html) |

如果按上游说明从源码编译，在配置 CMake 时加入 `-DBUILD_SHARED_LIBS=ON`。两种库都以 `libhs` 命名。自动生成规则包需要含编译接口的完整库，如 `libhs.so.5.8.0`。只有 `libhs_runtime.so` 时，使用下文的预生成包方式。

## 启用并确认加载

在启动 AgentMoss 的终端中设置以下变量。下面以 Ultrascan 为例，将 `/path/to/libhs.so.5.8.0` 换成实际库文件的绝对路径。在 x86_64 上将后端改为 `hyperscan`，路径指向对应的 Hyperscan 动态库。

```bash
export AGENT_MOSS_ACCEL_LIB=/path/to/libhs.so.5.8.0
export AGENT_MOSS_ACCEL_BACKEND=ultrascan
export AGENT_MOSS_ACCEL_DB="$HOME/.local/share/agentmoss/prefilter"
export AGENT_MOSS_ACCEL=1
```

`AGENT_MOSS_ACCEL_DB` 是供这一套规则专用的目录。选择可写的真实路径，容器内运行时使用容器内的路径。目录可以由服务创建。同一服务的多个 worker 可以共用目录，它们须使用相同的规则来源和动态库。

从仓库根目录启动服务。下面使用本地规则，不需要模型凭据。使用 L3 或服务管理器部署时，保留原有的启动参数和模型配置，把上面的四个变量加到服务环境，再重启该服务。

```bash
AGENT_MOSS_DISABLE_LLM=1 ./AgentMoss/.venv/bin/agent-moss server --host 127.0.0.1 --port 9090
```

服务在后台生成和加载规则包，加载前的请求继续使用 Python。另开终端，从仓库根目录查看磁盘包，路径与 `AGENT_MOSS_ACCEL_DB` 保持一致。

```bash
./AgentMoss/.venv/bin/agent-moss accel status --db "$HOME/.local/share/agentmoss/prefilter"
```

`state` 为 `ready` 时，`package.rules_accelerated` 给出可加速的规则数。再查看 AgentMoss 启动终端或数据目录下的 `agent_moss.log`。当前进程出现 `prefilter activated` 表示已加载。多个 worker 会分别记录。此时可以按[项目快速开始](../../README.md#快速开始)提交第一条工具调用。

## 更新规则或使用预生成包

自动生成默认开启。有效命令规则变化后，服务重新生成规则包并在后台切换，正在处理的请求继续使用原包。新改动的规则在新包加载前由 Python 检查。需要重启才生效的规则来源，仍须按其配置方式重启。设置 `AGENT_MOSS_ACCEL=0` 并重启 AgentMoss 可关闭预筛。

只读部署或只提供运行库的主机，可以使用预生成包。在使用完整库的构建机上，从仓库根目录按前面的步骤配置库和输出路径，然后执行以下命令。

```bash
./AgentMoss/.venv/bin/agent-moss accel build-db --profile linux --out "$AGENT_MOSS_ACCEL_DB"
./AgentMoss/.venv/bin/agent-moss accel status --db "$AGENT_MOSS_ACCEL_DB"
```

将整个目录（包括隐藏文件 `.package.lock`）复制给运行账户，保留包的目录结构。在目标服务环境设置 `AGENT_MOSS_ACCEL=1`、`AGENT_MOSS_ACCEL_AUTO_BUILD=0`，并配置后端、目标库及包目录。运行库必须与构建库的后端和完整数字版本一致，且支持目标 CPU。规则包只覆盖构建时选定的规则，其他规则继续使用 Python。手动替换包后，服务也会重新加载。

SDK 应用如需打包仅在内存中设置的规则，可将实际扫描器的 `export_accel_rules()` 结果保存为 JSON，用 `accel build-db --rules-file /path/to/rules.json --out "$AGENT_MOSS_ACCEL_DB"` 构建。将路径换为导出的文件，它应包含所需的全部规则。应用退出时可调用 `agent_moss.shutdown_acceleration()` 停止后台任务。

## 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 库文件存在，仍然加载失败 | 在服务所在主机或容器执行 `file -L "$AGENT_MOSS_ACCEL_LIB"` 和 `ldd "$AGENT_MOSS_ACCEL_LIB"`，核对架构并补齐标为 `not found` 的依赖 |
| 生成失败或长时间没有 `ready` | 确认使用完整的 `libhs.so`、服务账户可写入包目录，查看生成日志。服务会继续用已有的内存包或 Python 检查规则 |
| `accel status` 返回 `busy` | 正在生成或加载包，稍后重新查询 |
| 磁盘包已 `ready`，服务没有加载记录 | 查看服务进程实际使用的库、目录和开关。检查其日志中的 `prefilter activated` 或 `prefilter load failed` |

有关规则匹配和热更新的实现，见[预筛设计](预筛加速设计.md)。

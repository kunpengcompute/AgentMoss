# 命令规则预筛的工作原理

预筛负责缩小 Python 需要检查的命令规则范围。运行环境与开启方式见[预筛加速使用说明](预筛加速使用说明.md)。

## 如何筛选规则

构建器先用 Python 校验正则，再为能转换的规则生成更宽松的表达式。例如，原规则 `curl\s+https://` 要求两段文字之间有空白。预筛只检查这两段文字是否依次出现。通过预筛的文本仍要满足原规则。

转换器保留文字、分支和必要的顺序，可以放宽字符范围、重复次数和位置要求。无法完整解析、转换后超限或几乎匹配所有文本的表达式交由 Python 检查。原生库只编译去重后的预筛表达式，构建器同时记录每条原规则与表达式的对应关系。

对一次命令检查，扫描器固定使用一个内存包。它分别扫描预处理后的各份文本，合并候选规则，再按原有顺序运行 Python 检查。遇到原生扫描错误、结果不完整，或两种引擎对特殊字符的匹配可能有差异时，这次检查全部转回 Python。

## 规则包如何更新

1. 后台线程读取当前有效的命令规则，按规则原文和编译标志计算 SHA-256 指纹。如果读取期间规则来源发生变化，就重新读取。
2. 规则稳定后，构建器取得包目录的独占锁，重新检查规则来源和指纹。需要更新时写入 `building` 状态，编译规则并保存数据库、元数据和生成报告。
3. 写完后，构建器校验包的完整性并试加载，成功后将状态写为 `ready`。加载方持共享锁读取。编译或校验失败时，已加载的内存包仍可使用。
4. 各 worker 独立加载新包，在内存中切换。旧包由正在处理的请求持有，直到这些请求结束。检测请求无需等待磁盘读写或目录锁。

schema 4 包使用 `metadata.sha256` 校验元数据，再按元数据中的摘要校验报告和数据库。加载时也检查机器架构、后端和库版本。摘要用于发现内容损坏，规则包应由受信任的部署方提供。手动模式可读取完整的 schema 3 旧包，迁移到自动更新时应使用新的目录生成当前格式。

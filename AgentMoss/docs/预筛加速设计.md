# 预筛加速设计

命令规则原先由 Python 逐条检查。预筛为能够转换的规则生成一条要求更宽松的正则，交给加速库批量扫描；不可能匹配的规则可以跳过，其余仍由 Python 按原规则确认。规则不会因为无法加速而失效。

例如原规则为 `curl\s+https://`，预筛保留“curl 在前、https:// 在后”，中间允许任意内容。缺少这些文字时可以排除这条规则；有这些文字时仍检查原规则，确认中间是否真的是空白。

## 准备加速包

```text
读取当前有效的命令规则
        ↓
Python 校验原规则，完整读取支持的规则结构
        ↓
生成一条简化正则，检查它是否仍有筛选作用
        ↓
去重后交给原生库批量编译
        ↓
保存数据库、规则对应关系和生成报告
        ↓
校验并试加载，最后将状态改为 ready
```

转换不了、生成结果超限，或简化后搜索任何文本都会命中的规则，直接使用 Python。编译失败能定位到某个表达式时，移除它及对应规则的预筛条件，再编译剩余表达式；最多调用编译器 16 次。内存不足、原生库不可用或无法完成构建时，停止生成，保留已加载的内存数据库。磁盘包可能已被覆盖，重启时先用 Python 再重建。

## 简化规则怎样生成

解析器从左到右读取完整规则，记录连接顺序、分支、括号和重复次数。只有整条规则都在支持范围内才转换，不会从未读懂的规则中截取部分文字。

| 可以读取的写法 | 简化时怎样处理 |
|---|---|
| 普通文字、转义标点、控制字符转义、固定长度十六进制转义 | 保留 ASCII 字符；非 ASCII 字符放宽为任意内容 |
| 正向 ASCII 字符集合及范围，如 `[abc]`、`[a-z]` | 保留字符范围；忽略大小写时同时包含大小写字母 |
| 取反集合、包含非 ASCII 或字符类别的集合，及 `.`、`\s`、`\d`、`\w` 等类别 | 放宽为任意内容 |
| 顺序连接、`|`、普通分组、`(?:...)` | 保留顺序和全部分支 |
| `?`、`*`、`+`、`{m}`、`{m,}`、`{m,n}` 及其懒惰写法 | 单字符或字符集合的小范围重复保留次数；其他重复按最少次数放宽，不能把可选内容改为必需 |
| `^`、`$`、`\A`、`\Z`、`\b`、`\B` 及四类前后断言 | 去掉位置或断言要求；断言内部也必须完整读懂 |

集合中的歧义写法，例如 `&&`、`||`、`~~`、`--`，不转换。表外语法也整条使用 Python，例如规则内模式声明、命名分组、反向引用、条件分组、原子分组、占有量词和数字转义。规则是否合法仍以产品所在 Python 为准。

命令规则检查统一忽略大小写；其他外部匹配模式不参与预筛。解析器使用公开的 Python 正则接口校验原规则，不读取 Python 内部解析结构。

转换只会减少匹配要求：字符范围可以扩大，位置要求可以移除，但不能丢掉分支、交换顺序或把不必出现的部分改成必须出现。测试进一步检查“Python 原规则匹配时，预筛必须留下这条规则”。

## 后台怎样发现规则变化

后台通过只读入口取得有效命令规则，沿用业务的覆盖顺序和启用状态。读取前后比较来源内容，期间发生变化就重试，不把读取错误当成空规则。

规则原文和实际编译标志去重、排序后计算 SHA-256 指纹。不能转换的规则也计入指纹。指纹相同仍要检查包文件是否完整、环境是否兼容，防止损坏文件一直被跳过。

首次开启或规则改变后，等待至少一秒稳定，再取得目录独占锁。取锁后重新检查规则、来源归属和失败重试时间，避免多个进程重复生成。依次保存 building、覆盖并刷盘包文件、校验和试加载、再次核对规则、保存 ready。仅状态文件使用短暂的 `.status.tmp`，不创建数据库备份或版本目录。

对于已缓存、需要重启才改变的来源，在业务首次读取前记录内容版本。磁盘来源后来变化，旧进程停止自动生成，防止错峰重启时覆盖新进程的包。后台读取不修改业务扩展缓存，也不写回配置。

加载时持共享锁，只接受完整的 ready 包。后台按生成编号和元数据摘要识别同一路径的更新；请求只取已经加载的内存对象，不做读盘、指纹计算或文件锁等待。

## 检测和热更新

1. 请求取得内存中已加载的包；未开启、尚未加载或没有对应条件时，使用 Python。
2. 按原规则文字及实际忽略大小写等标志逐条对应，包可以只覆盖部分规则。新改规则先用 Python，未改规则继续加速。
3. 每份预处理后的文本分别调用加速库，合并各份文本的候选规则，再由 Python 完整检查。任一份扫描失败或结果不完整，本次规则扫描全部使用 Python。
4. 一次规则扫描固定使用一个包。后台在请求之外读取并验证新包，成功后切换；在途扫描持有旧包直到结束。各 worker 独立加载。

普通中文文本可以预筛。少数控制字符、特殊大小写字符和代理码点会让本次扫描全部使用 Python，保护 Python 与原生库之间的字符语义差异。

加速包按规则内容绑定，检查文件完整性、机器架构、库类型和版本。它不绑定 Python 小版本；运行时能力检查不通过时回到 Python。原生数据库由线程同步保护，并处理 fork 和退出时的资源清理。

schema 4 使用独立的 `metadata.sha256` 保存完整元数据的 SHA-256 摘要（64 个小写十六进制字符及换行）。构建器在发布前写入并自检；后台加载和磁盘 `status` 在解析元数据前校验摘要，再检查元数据结构、报告和数据库摘要。校验文件缺失或损坏会拒绝整包，规则编号即使仍在合法范围内也不能绕过损坏检查。摘要用于检测损坏，包仍需由可信部署流程维护。

## 代码入口

| 文件 | 职责 |
|---|---|
| `engine/regex_subset_parser.py`、`prefilter_simplify.py` | 完整读取规则并生成简化正则 |
| `engine/prefilter_build.py`、`prefilter_manifest.py`、`prefilter_disk.py` | 编译、格式和文件完整性校验 |
| `engine/prefilter_rule_source.py`、`prefilter_fingerprint.py` | 只读规则快照和内容指纹 |
| `engine/prefilter_storage.py`、`prefilter_autobuild.py` | 固定目录、状态、文件锁及自动生成 |
| `engine/prefilter_native.py` | 原生库编译、加载、扫描及释放 |
| `engine/prefilter.py`、`prefilter_reload.py` | 规则对应、候选计算与后台换包 |
| `engine/heuristic.py` | 命令扫描中接入预筛，保留 Python 最终判定 |
| `accel_cli.py`、`server/app.py`、`__init__.py` | CLI 操作、worker 生命周期和 SDK 退出接口 |

文件路径相对 `agent_moss/`。开启及刷新方式见 [使用说明](预筛加速使用说明.md)。

# 预筛加速测试说明

## 覆盖内容

测试覆盖默认关闭、规则转换、真实原生库调用、规则对应、异常回退、自动生成、热更新、并发扫描、fork 和资源清理。规则差分和小字符集合穷举检查 Python 原规则匹配时不会被预筛排除。

自动更新重点验证：

- 规则读取不写回配置、不污染业务缓存；读取中发生变化时放弃本次快照。
- 启动时实际读入的内容与来源标识一致；规则修改后又回滚，也不会让旧进程错误取得发布资格。
- 规则稳定后生成，相同内容不重复生成；多个进程竞争时只生成一次，同一失败输入共用重试间隔。
- 更新失败保留旧内存数据库；原生库在某个进程中分配内存失败，不破坏完整的共享磁盘包。
- 在 building、各包文件写到一半、试加载后和 ready 前后强制结束生成进程，重新加载只能接受完整包，否则使用 Python 后重建。
- 停止时不无限等待提交，也不提前释放仍在写文件的锁；fork 后子进程不解锁父进程。

## 运行测试

先按[开发与测试](../README.md#开发与测试)安装源码和测试依赖，激活测试环境，再进入 `AgentMoss/` 组件目录。

不安装原生库也能运行规则转换、默认关闭和异常回退测试；需要真实原生库的用例会跳过：

```bash
AGENT_MOSS_ROOT="$PWD" AGENT_MOSS_DISABLE_LLM=1 python -m pytest \
  tests/test_prefilter_*.py tests/test_regex_subset_parser.py -q
```

在 Linux x86_64 环境中，按[使用说明](预筛加速使用说明.md)准备完整的 Hyperscan 库，
设置测试库路径后运行同一组命令：

```bash
export AGENT_MOSS_TEST_HS_LIB=/实际路径/libhs.so.5.4.2
AGENT_MOSS_ROOT="$PWD" AGENT_MOSS_DISABLE_LLM=1 python -m pytest \
  tests/test_prefilter_*.py tests/test_regex_subset_parser.py -q
```

`AGENT_MOSS_TEST_HS_LIB` 只控制测试，不替代服务部署使用的 `AGENT_MOSS_ACCEL_LIB`。
当前部分专项用例显式使用 `hyperscan` 后端和 x86_64 架构假设，不能仅替换库路径就作为 ARM 完整验收。
Ultrascan 部署需要结合实际平台检查规则编译、加载、更新和回退行为。

## 独立安装检查

`tests/verify_prefilter_wheel.py` 检查已安装包的原生库加载、热更新和在途旧数据库扫描。
它要求从源码目录之外执行，并确认 `agent_moss` 来自指定的安装目录。先将构建出的 wheel
安装到独立目录，然后指定安装路径、完整编译库、同版本运行库和后端：

```bash
PYTHONPATH=/实际路径/wheel-install python /实际路径/AgentMoss/AgentMoss/tests/verify_prefilter_wheel.py \
  --install-root /实际路径/wheel-install \
  --compile-lib /实际路径/libhs.so.5.4.2 \
  --runtime-lib /实际路径/libhs_runtime.so.5.4.2 \
  --backend hyperscan --expect-runtime-only
```

ARM 环境使用对应的 Ultrascan 库，并设置 `--backend ultrascan`。完整库和运行库的数字版本必须一致。

## 结果判读

记录实际使用的 CPU 架构、Python 版本、原生库版本以及通过、跳过和失败数量。
缺少原生库、Python 不支持某种正则语法或未配置模型时，相关测试可能跳过；跳过不计为验证通过。

测试默认隔离 AgentMoss 的运行时数据，避免读取本机控制台配置。强制结束进程的恢复测试不能代替真实掉电验证，
单机测试也不能说明网络文件系统或长期负载下的行为；这些场景需要在目标部署环境单独检查。
